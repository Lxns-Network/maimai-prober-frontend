# 更新日志

统一载体为前端仓库 `public/docs/changelog.md`，覆盖玩家与第三方 API 开发者关心的变化。同级 Go 后端通常在 `../maimai-prober`，没有独立更新日志。

## 触发与范围

- 只有用户明确要求撰写或更新日志时才修改文件；仅要求审查时只报告问题。功能开发、修复、提交、push、打 tag 或发版均不自动包含更新日志工作。
- 保持现有 `agents/openai.yaml` 的显式调用策略。使用本 skill 不授权提交、推送或发布。
- 优先采用用户指定的文件、提交范围、版本与日期。只有任务覆盖整个发布批次时才检查前后端完整范围，不为局部条目修改扫描两个仓库的全部历史。
- 从当前日志、Git 历史和对应实现核对发布边界与最终行为。提交日期、日志日期或“已合并”不能单独证明已上线；边界不明且影响归并时说明缺口，先完成不依赖它的整理，不猜测发布状态。

## 收集与筛选

先检查工作区已有改动和现有日期小节，再读取所需 diff 与实现；提交标题只作线索。按以下规则处理：

| 变化                                                                    | 处理                     |
| ----------------------------------------------------------------------- | ------------------------ |
| 新功能、交互/业务规则、已发布缺陷修复、外部 API 契约、可感知体验改善    | 记录最终对外行为         |
| 纯重构、注释、内部文档、CI/脚本/配置、测试/基准、普通依赖升级、内部运维 | 无外部行为变化则不写     |
| 隐藏且未开放的功能                                                      | 不写成已可用能力         |
| 同一未发布窗口内引入又完全回滚的功能                                    | 抵消，不写               |
| 针对本期未发布功能的修补与打磨                                          | 折叠进原条目，不另列修复 |

用外部结果判断，不按提交类型机械过滤：依赖升级若修复了用户可见故障，记录故障修复；内部性能数据不能直接转述成用户体感提升。

## 归并与措辞

- 按同一功能区域或同一用户可感知问题归并，不逐条翻译 commit。多轮实现、样式调整与未发布修复提炼成最终成果。
- 单日 2～6 条仅作粒度参考，超过时复查可合并项；不为凑数强行合并无关功能，也不拆分凑足条目。
- 玩家条目描述场景、能力与可见变化，不写内部文件、函数、数据库、状态机或实现术语。
- API 条目依据受众划分：新增可选能力也属于开发者条目，不限于要求调用方改代码的变更。准确保留接口路径、字段、协议、状态码、默认值和兼容影响。
- 只保留有行动价值的细节。常规控件类型、步长、持久化实现无需说明；配额、调用方默认值、迁移步骤必须说明。自动保存、默认行为或交互形态若本身就是本次变化，需写清。
- 沿用「新增」「支持」「优化」「移除」「现在……」等句式；修复条目写为「修复……的问题」，交代场景与现象。
- 前后端协同变化合为业务成果，不加 `[前端]`、`[后端]`、`[API]` 标签或分区。不新增商业游戏名、逆向工具名或私有数据来源；使用查分器、曲目、谱面等中性表述。

需要拿捏粒度、API 表述或破坏性变动排版时，读取 [references/writing-examples.md](references/writing-examples.md)。示例不作为实现或发布证据。

## 写入与校验

- 保持顶部 `# 更新日志` 与 `---`。日期标题使用 `## YYYY/M/D`，月份、日期不补零，按日期倒序排列；同日已有小节则更新该小节。
- 一级条目用 `-`；复合条目以冒号结尾，子条目缩进 2 个空格。标识符、参数与状态码用反引号；站内链接用 `/...` 路径。
- 公开贡献或 issue 链接可在行尾使用 `（[#编号](完整URL)）`；只使用已核实的链接。
- 破坏既有契约时，在当日普通条目下方加 `### ⚠ 破坏性变动`，说明受影响对象及替代方式；未知迁移方案不得编造。
- 审查最终 diff：每条都有变更证据，没有重复或未发布修复噪声，日期、链接、字段与默认值准确，既有工作区改动未被覆盖。
- 使用仓库现有 Markdown 格式检查。纯日志修改无需运行应用测试或构建；有渲染语法变化时再核验相应展示。
- 交付时简述涵盖范围、实际验证和证据缺口。查阅历史使用只读 Git 命令；若另获暂存授权，普通 `git add` 即可，不需要 `-f`。
