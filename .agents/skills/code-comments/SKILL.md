# 代码注释

让注释补足代码无法表达的契约与工程依据。遵循当前仓库 `AGENTS.md`；案例不替代当前实现。

## 范围与改写克制

- 仅审查时报告问题，不修改文件。整理注释时只处理请求范围内的注释，不顺手重构、重命名或修复业务逻辑。
- 事实准确、信息不冗余的既有注释保持原样，不为润色、统一风格或排版而改写。无需改动也是有效结果。
- 先判断是否需要这条注释，再决定如何修改。不以新增/删除行数衡量质量；缺失的必要契约应补充。
- 开始前检查工作区与暂存区，区分已有改动和本次改动。工作区不干净时保存本次目标文件的起始副本，不能把与 `HEAD` 的全部差异归为本次工作。

## 保留、删除还是修正

| 内容                                                                           | 处理                                         |
| ------------------------------------------------------------------------------ | -------------------------------------------- |
| 签名外的调用契约：抛错条件、副作用、排序要求、时间基准、单位、资源释放、所有权 | 保留；缺失时在函数外的 JSDoc 补充            |
| 实测常量依据、平台兼容原因、硬件帧预算、不可自解释的算法约束                   | 保留必要的条件、数据与推导                   |
| 语法复述、类型直译、无额外契约的构造函数或简单辅助函数说明                     | 删除                                         |
| 准确且有用的既有说明                                                           | 保持原样                                     |
| 事实错误、已过时或缺少必要条件                                                 | 核对实现后最小修正；证据不足时说明待核实点   |
| 仅叙述改动历史、优化战报或心得                                                 | 删除；若包含仍约束实现的工程原因，保留该原因 |

不要把许可证、工具指令当作普通注释清理。`@ts-*`、lint/format 指令、`/* @__PURE__ */`、三斜线引用等可能影响编译、检查或产物；修改它们需按行为变更验证。

## 内容与文风

- **JSDoc 面向调用方**：说明非显然的输入约束、返回语义、`@throws`、副作用与生命周期，不复述函数名、参数类型或内部执行步骤。
- **内部注释解释原因**：保留实测依据、兼容问题或难以直接看出的不变量，不逐句翻译代码。注释任务不授权通过重构让代码自解释。
- **实测依据不能压成泛泛目的**：删去后若无法复核或安全修改常量，应保留样本条件、单位、拟合误差与关键推导。工程测量与“优化后更快”的战报须区分。
- **事实可核验**：新增或修改的数值、比较关系、单位、默认值、抛错与状态恢复声明均核对实现；测量结论核对已有采样依据，不编造新测量。
- **术语沿用代码**：如 `Hold`、`Touch Hold` 与对应标识符保持一致，不借整理注释推行中英术语替换。物理量标明 `ms`、`s`、`beat`、`px`、`rad` 等单位。
- 常规注释用一两句话；多个独立契约才分点，不堆小标题、套话或俚语。来源表述沿用“实测采样”“录像拟合”，不新增商业游戏名、逆向工具名或私有数据来源。

涉及谱面引擎的实测常量、时钟、Canvas 兼容或术语时，按需读取 [references/engineering-cases.md](references/engineering-cases.md) 中对应案例。

## 验证与交付

1. 对照本次起始状态审查完整 diff，确认没有改动代码、字符串、模板、正则字面量、JSX 文本或工具指令；检查新增、删除与重命名文件，不能静默略过。
2. 不使用正则“去注释再去空白”证明逻辑未变：它会误删字符串内容，也会遗漏换行引起的自动分号插入变化。批量变更需要自动验证时，使用支持 TS/TSX 的解析器比较语法结构与字面量，并另外核对工具指令；解析失败不得当作通过。
3. 运行目标文件的格式检查与相应 lint。当前格式化工具为 Oxfmt，命令以 `package.json` 为准。行为变更按 `AGENTS.md` 完成所需检查；普通文字调整无需机械启动开发服务器或性能基准。
4. 简要汇报删除的冗余、修正或补充的契约、实际验证结果及未核实项。人工 diff 审查不能宣称已通过自动化逻辑等价验证。
